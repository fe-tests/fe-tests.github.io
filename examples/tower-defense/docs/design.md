# 塔防要塞 · 需求与设计

> 本文件记**设计**（要做什么、为什么这么做）；过程流水与踩坑记在 [devlog.md](devlog.md)。

## 1. 需求与目标

- 一句话：一个**功能完备、可玩性较高**的多关卡塔防放置游戏，**移动端交互优先**，纯原生 Canvas 2D 实现，零依赖零网络。
- 目标用户与场景：
  - 主场景是**手机竖屏单手**（通勤、排队，390×720 CSS px 左右），拇指完成选塔 / 落塔 / 升级 / 出售 / 技能；
  - 次场景是**桌面键盘党**（宽屏 + `1-9` 选塔 / `空格` 开波 / `J K L` 技能的连招流），要求横屏与竖屏都自适应，不靠「缩小桌面版」糊弄；
  - 展示点：ES Module 分层、纯逻辑可 Node 校验、程序化美术与音效、固定步长与视口剔除的性能手法、移动端手势工程细节。
- 验收标准（逐条可测）：
  1. 首屏零外部请求，进入主菜单到能开始第一关 < 3 秒；
  2. 移动端在**第一关 60 秒内**完成「选塔 → 落 3 座塔 → 升级 1 座 → 放 1 个技能 → 手动开波」全链路；
  3. 12 关全部能被自动玩家打通（`tools/smoke.mjs` 逐关断言通关且单关塔数 ≤40）；
  4. 前 3 关留有胜余（≥2 星、漏怪 <35%），10~12 关保持压力（至少一关有漏怪）；
  5. 零塔必败：不造塔一定输（前 6 关在第 2~3 波被打穿）；
  6. 无尽模式能持续跑分（自动玩家 ≥8 波，波次公式每 5 波含 BOSS）；
  7. 刷新后进度可恢复（星数 / 解锁 / 无尽最佳 / 设置），禁用 `localStorage` 时不报错；
  8. 装配全链路在无浏览器环境可验证：`tools/headless.mjs` 用替身 DOM 跑真实 `Game.frame` 与 `main.js` 入口装配，38 项断言含「连打一关拿到 ★3」与「页内 `TD.selfTest()` 全绿」；
     `tools/smoke.mjs` 54 项断言覆盖数据表、模块图、DOM / CSS / 键位文案契约与逐关平衡；
  9. 触控落点不被手指遮挡（落点在指尖上方 36px）；缩放可覆盖全图到 2.6×；
  10. 页面暴露 `window.TD`，控制台可脚本化驱动与自检。
- 非目标（明确不做）：
  - **迷宫式塔防**（自由造墙改变寻路）：选固定路径 + 可建格 / 石台，理由见 §7；
  - 科技树、装备、抽卡、离线收益、挂机产出；
  - 云存档、排行榜、社交分享；
  - PvP、多人同图、回放系统；
  - 外部贴图包 / 图标字体 / 音效文件（全部程序化）；
  - 3D 视图、WebGL、多分辨率素材包；
  - 局内存档（刷新即重开本关，见 §6）。

## 2. 玩法 / 使用流程

```
boot(引导守卫) → menu → levels(选关/无尽) ─┐
                                          ├→ playing ⇄ paused → over(win | lose | endless)
                    主菜单「继续第 N 关」────┘        ↓
                                            win: 解锁下一关 → levels / 下一关
                                            lose: 提示 → 重打本关
```

局内波次状态机：

```
intermission(FIRST_WAVE_GAP=14s，之后 WAVE_GAP=9s)
   → startWave(manual?提前奖励) → spawning(queue 按 delay+gap 出怪)
   → 全清 → clear(reward 入账) → intermission
   → 波次耗尽且基地存活 → win；基地 hp≤0 → lose
```

关键规则：

- **建造**：点塔卡 → 射程圈跟随 → 点格子落位（或拖到目标格松手）；`连放`开启则保持选中态可连续建造；
  长按 0.4 秒 = 在点中的格子直接建造；`canBuild` 统一裁决（越界 / 道路 / 障碍 / 已有塔 / 石台限制 / 塔数上限 / 金币不足）。
- **升级与出售**：点塔开抽屉；3 级；升级费用逐阶涨；出售返还**已投入金币的 70%**（`SELL_RATE`），出售需二次确认。
- **目标优先级**：最先 / 最后 / 最强 / 最弱 / 最近，逐塔可切；BOSS 波推荐「最强」。
- **技能**：☄️ 流星雨（需落点，真实伤害）、🧊 冰封（全场冻结，BOSS 冻结时长 ×0.5）、💰 富矿（立得金币 + 60 秒赏金 +25%）。
- **经济**：起始金币 = 关卡金币 × `BAL.startGold`；击杀赏金；波次奖励；提前开波奖励 = 剩余等待秒 × 1.6。
- **漏怪**：按敌人 `leak` 扣基地血量，**单次漏怪伤害上限 = 基地上限的 25%**（防止 BOSS 漏一次直接崩盘）。
- **评星**：通关按得分对照**自动推导**的阈值给 1~3 星；1 星解锁下一关；无尽不计星，只记最高波次与分数。
- **引导**：底部常驻一行操作提示（横屏隐藏）；帮助页有 4 个页签（操作 / 塔 / 敌人 / 系统与键位）。

## 3. 数据与算法

纯逻辑层全部包在 `/* ENGINE-START */ … /* ENGINE-END */` 锚点内：`config.js`、`towers.js`、`enemies.js`、`levels.js`、`engine.js`，
不引用 DOM，可被 `tools/smoke.mjs` 直接 import 校验。

**坐标与网格**：`TILE=64`，`GRID_W×GRID_H = 16×12`，逻辑分辨率 `1024×768`；世界坐标以像素计，塔中心 `(x+0.5)*TILE`。
`buildGrid(level)` 产出网格对象 `{w, h, cells(Int8Array), at(x,y), base, spawn}`，索引 `y*w+x`；
单元类型 `CELL.EMPTY=0 / PATH=1 / BLOCK=2 / PAD=3`。路径航点轴对齐（保证沿路推进与直线飞行两套算法都简单），
末点必须等于基地；`selfCheck()` 断言这一不变量。装饰障碍随机撒，且**避开道路及其八邻格**，避免「贴路障碍堵住视觉通路」。

**波次表**：DSL 书写 `G(敌人, 数量, 间隔, 首次延迟, 线路, 精英级)` 与 `W(奖励, ...组)`，12 关共 130+ 波。
`finalize()` 自动推导星级阈值：

```
expect = Σ( 敌人赏金×10 ×(1 + 精英×1.8) + 波次奖励×10 + 200 ) + 基地上限×80
stars  = [0.55, 0.76, 0.92] × expect  → 取 50 的整数倍
```

因此**任何波次改动都会自动重算阈值**，手写 `stars` 会破坏单调性（`selfCheck` 会报错）。

**战斗数值**：伤害类型 5 种（物理 / 魔法 / 火焰 / 毒素 / 真实）对护甲与魔抗走不同减免；
结算顺序：`基础伤害 × BAL.towerDmg` → 类型减免（护甲 / 魔抗 / 相性）→ 塔特性加成（对空、溅射、穿透、链式衰减、光环、持续伤害）→ 状态结算。
状态：slow / freeze / stun / burn / poison / shield / heal / haste / phase / stealth；
敌人词条：飞行、潜行、相位护盾、护盾再生、冲锋、召唤、死亡分裂、自爆、免疫减速、机械、治疗光环、加速光环、首领；
精英倍率 `ELITE[1]`（精锐）与 `ELITE[2]`（精英）叠血量与护甲。
波次缩放 `scaleEnemy(def, waveIdx, lvMul)`：血量按 `hpGrowth` 递增、护甲按 `armorGrowth` 缓慢成长、BOSS 用 `bossHp` 单独缩放。

**目标选择**：按模式给候选打分（沿路进度、到基地距离、当前血量、到塔距离），BOSS 在「最强」模式下权重压倒性；
每塔缓存目标直到死亡 / 出射程，避免每帧全量重算。

**事件流（表现与逻辑的唯一接口）**：引擎 `emit(st, kind, data)`，`game.js` 每帧 `drainEvents` 单点消费，
映射到音效 + 粒子 + 震动 + UI 提示。共 23 类：
`build / upgrade / sell / spawn / early / wave / kill / bossdie / dmg / lava / phase / charge / summon / leak / lose / aura / clear / win / boom / hit / meteor / blizzard / greed`。
射击与光束**不发事件**，由 `st.shots.length` / `st.beams.length` 的增量派生——高频音效不产生事件洪水。

**时间与步进**：固定步长 `STEP=1/60`，累加器驱动，每帧最多 `MAX_STEPS_PER_FRAME=8` 步，倍速时预算 ×speed；
`dt = clamp(now-last, 0, .25)`，积压超过预算直接丢弃（不追帧雪崩）。暂停时引擎冻结（粒子仍衰减 ×0.4），
`visibilitychange` 自动暂停。切后台回来不会「跳波」。

**可复现**：`mulberry32 + seedOf`，关卡 seed 固定为 `levelId*7`，无尽用 `Date.now()%100000`；同关同 seed 的模拟结果稳定，便于回归。

**自动玩家（可玩性的证明，也是平衡回归的仪器）**：`makeAi(st) + aiThink(st, ai)`——
对可建格按「覆盖道路条数 + 邻近聚簇」贪心集合覆盖排序选位，先补主力塔再升级（`aiUpgradeGold / aiExpandGold` 两个门槛），
塔数上限 `cap = min(maxTowers, 20)`，BOSS 波切「最强」目标；`simulateLevel(level,{ai:true})` 跑完整关。

**调参单点**：所有全局倍率在 `config.js` 的 `BAL` 一个对象里（塔伤 / 射速 / 造价 / 敌人血量与成长 / 赏金 / 起始金币 / 波次奖励 / AI 门槛），
数据表只写原值。且**金币缩放不进评分模型**（分数只用原始赏金与奖励），所以调经济不会让星级阈值失效。

**存档算法**：`stars` / `best` 按关卡 key 合并取**历史最大**；数字字段清洗（fx≤2、speed≤2 且 ≥0、unlocked≥1、星级 ≤3），
`totalStars` 由星级重算；损坏 JSON 直接重建；`localStorage` 不可用时退化为内存对象。

## 4. 渲染与视图

- **分工**：DOM 只承载 HUD 文本、覆盖屏、塔盘、抽屉（可访问、可换主题、不吃画布性能）；
  Canvas 2D 画世界（地形、塔、敌人、弹道、粒子）；图标用 emoji（零依赖换可读性）。
- **图层顺序**：地形 → 出怪口 → 网格 → 流向箭头 → 基地 → 射程圈 / 准星 → 塔 → 敌人 → 弹道与光束 → 伤害数字 → 粒子层 → 环境粒子 → 环境遮罩 → 屏幕空间标记与闪光。
- **地形烘焙**：`buildTerrain(st)` 把地块、道路、装饰、石台一次画进 1024×768 离屏画布，缓存键 = `levelId|theme|env|weather`，
  主循环只 `drawImage` 一次；关卡内不变的东西绝不重画。
- **DPR 与缩放**：`dpr = min(DPR_MAX=2, devicePixelRatio × (档位0 ? 0.8 : 1))`；
  画布 CSS 尺寸由容器给（`flex:1`），`resize()` 重设像素缓冲并 `fitView`；
  视口为 letterbox 适配：`fit = min(cssW/1024, cssH/768)`，缩放范围 `fit .. 2.6`，平移带边界钳制。
- **剔除**：`viewRect()` 给可视矩形，塔 / 敌人 / 弹道 / 粒子按矩形跳过；屏幕外的出怪口与基地画**方向箭头**（屏幕空间），
  缩放时不丢信息。
- **特效预算**：`Fx` 按档位控上限（流畅 120 / 均衡 260 / 华丽 460 粒子），池满时淘汰**剩余寿命最短**的粒子；
  震屏与闪光在 `prefers-reduced-motion` 下降幅 65%。
- **环境表现**：`night / sandstorm / lava / snow / swamp` 五种环境遮罩（沙暴期射程 -15% 且有飞沙条纹与文字提示；
  熔岩每 6 秒灼烧地面敌人；风雪让减速塔增强），`rain / fog / ember / spore` 四种天气粒子；
  这些都读引擎的 `envPhase / envRangeMul`，**表现层不自己造规则**。
- **降级**：无 WebGL 依赖；`prefers-reduced-motion` 下粒子、闪光、准星抬升（×0.6）与动画全面收敛；
  `?fps=1` 显示帧率 / 粒子数 / 敌人数的诊断条。

## 5. 交互与输入

| 场景 | 手势 / 按键 | 行为 |
| --- | --- | --- |
| 建造 | 点塔卡 → 点格子 | 选中 → 显示射程圈 → 落塔 |
| 建造（触屏） | 点塔卡 → **按住拖到**格子 → 松手 | 拖动显示准星（落在指尖上方 36px），松手落塔 |
| 快速建造 | **长按**格子 0.4s | 直接在点中格建造（选中的塔卡） |
| 连续建造 | 底部 **🔁 连放** | 放完不退出选中态 |
| 看地图 | **双指捏合** / **双指拖动** / 单指拖动 | 缩放（`fit..2.6`）/ 平移 |
| 看地图 | **🧭 / ＋ / －** 按钮 | 一键看全图 / 逐级缩放 |
| 管理 | 点塔 | 打开底部抽屉（升级 / 目标 / 出售） |
| 出售 | 抽屉「卖」**两次** | 第一次变「确认?」并抖动，第二次成交（3 秒超时撤销） |
| 技能 | 点技能按钮（☄️ 需落点）/ 桌面 `J K L` | 进入待落点态（准星跟随）/ 立即施放。技能不给 `Q W E` 是因为 `W` 已绑平移，同手位不能撞键 |
| 开波 | 底部 **🌊 开波** / `空格` | 提前开波，给剩余时间 ×1.6 金币 |
| 倍速 | `×1 ×2 ×3` 按钮 | 固定步长下加速 |
| 全局 | `P` 暂停 · `Esc` 取消 / 返回 · `?` 帮助 · `U` 升级 · `X` 出售 · `1-9` 选塔 · `F` 看全图 · `+/-` 缩放 · 方向键/WASD 平移 | 覆盖屏与游戏内快捷键分工不冲突：`input.js` 只映射游戏内键，UI 自己接 `p` / `?` / 覆盖屏内的 `Esc` |

判定阈值：拖动最小 6px 才 pan/drag；点击位移 <10px 且 <500ms；长按 400ms；`pointerType==='mouse'` 时**不做 36px 抬升**（鼠标要精确落点）。

输入冲突处理：

- 画布 `touch-action:none` + 页面 `overscroll-behavior:none`：拖动画布不会触发浏览器滚动 / 下拉刷新 / 双击缩放（viewport 也禁缩放）；
- 底部塔盘 `touch-action:pan-x`：横向滑动选塔与画布手势互不干扰；
- `setPointerCapture` 锁指针（`try/catch` 包裹），拖动跨出画布不丢事件；抑制 `contextmenu`；
- 多点触控：`pointerId` 记账，两指进入 pinch 模式时丢弃单指 pan，避免「缩放 + 平移 + 拖动建造」互相打架；
- 暂停 / 覆盖屏期间 `input.setEnabled(false)`，遮罩下不会误建造；
- 覆盖屏按钮全部 ≥44px 命中区，技能按钮 56 / 52 / 48px，顶栏图标按钮 44px。

可访问性：图标按钮带 `aria-label`，开关用 `aria-pressed`，`:focus-visible` 有可见焦点环，
`prefers-reduced-motion` 生效，文案中文、暗色主题下正文对比度 ≥ 4.5:1，
关键状态（金币、血量）同时有文本与颜色（血量低时变红并显示阈值警示）。

## 6. 状态与持久化

- 局内状态（塔、敌人、波次）**不持久化**：刷新即重开本关。理由是塔防单关 3~5 分钟，
  中途序列化整套实体（状态效果、弹道、粒子）复杂度与收益不成比，且局内随机已用 seed 复现。
- 存档键 `tower-defense.save.v1`，结构：

  ```js
  { v: 1, unlocked: 1, stars: {'1': 3}, best: {'1': 51234},
    endless: { bestWave: 0, bestScore: 0 }, totalStars: 0,
    sound: true, grid: true, dmgNum: true, keep: true, auto: false,
    fx: 1, speed: 0 }        // fx / speed 是档位与 SPEEDS 的「下标」，不是倍速本身
  ```

- 自愈规则：缺字段回落默认；类型错乱丢弃；`stars` 值上限 3、`best` 不设上限；`fx/speed` 夹在 `[0, 档位上限]`；
  `unlocked ≥ 1`；`totalStars` 由 `stars` 重算；解析失败直接重建并回写。
- 写入策略：`stars`/`best` 按关卡 key 取历史最大合并，`endless` 逐字段取大，标量直接覆盖；每次改动即时落盘。
- 恢复策略：进入主菜单读档；「继续第 N 关」= `min(unlocked, LAST_LEVEL)`；关卡列表按 `isUnlocked(id)` 灰掉未解锁关卡。
- 清理：关卡选择页「清空存档」**两次点击确认**（4 秒超时撤销），不用浏览器原生 `confirm`（移动端体验差且样式不可控）。
- 隐私模式 / 禁用存储：`localStorage` 读写包 `try/catch`，退化为内存对象，本局内功能完整，刷新丢进度。

## 7. 关键取舍

| 选择 | 为什么 | 放弃的方案与原因 |
| --- | --- | --- |
| 固定路径 + 可建格 / 石台 / 塔数上限 | 手机上路径可读、局势可预判，决策集中在「塔位 / 升级 / 技能时机」；渲染与寻路都简单，性能可预测 | 迷宫塔防（造墙改寻路）：手机上手指挡视野、误触代价高、寻路开销与「随手一建就通关」的破坏平衡 |
| 引擎纯逻辑 + 事件流 → 表现层 | 玩法可被 Node 直接测试与自动对局，平衡可量化回归；渲染与音效永不影响判定 | 直接在渲染循环里改状态：写起来快，但无法自动化验证，「可玩性」只能靠人肉点 |
| 全局倍率集中在 `BAL` 单点 | 一次调参全盘生效，数据表保持可读原值；金币缩放与评分模型解耦 | 在数据表里乘系数：改一个关卡要重算 130 波，且经济改动会打爆星级阈值 |
| 星级阈值由波次表推导 | 关卡内容迭代时零维护成本，单调性由 `selfCheck` 保证 | 手填阈值：三关一改就要全线重校，实践中一定会漂移 |
| 程序化美术与音效（含 emoji 图标） | 零依赖、零网络、体积可控（gzip 后约 82 KB）、无外部资源许可风险 | 贴图包 / 图标字体 / 音频文件：观感上限更高，但要引入 vendor、许可与加载失败路径 |
| 地形每关烘焙一次 | 12 关 × 每关一次烘焙，换主循环每帧只 1 次 `drawImage`，低端机帧率保障 | 每帧程序化重画地块与装饰：直接掉到 30fps 以下 |
| 漏怪伤害上限 25% 基地上限 | BOSS 漏一次不至于瞬间判死刑，玩家有反打窗口；压力仍在 | 全额扣血（BOSS 漏怪 8~12 点）：后段关卡变成「一次失误 = 直接结算」，挫败感强 |
| 二次确认用于出售与清档 | 移动端误触率高，破坏性操作给撤销机会 | 原生 `confirm`：样式不可控、打断手势流 |
| 倍速走固定步长 | ×3 时弹道 / 状态 / 判定与 ×1 完全一致，快进只是「同样的规则跑快」 | 放大 dt：会漏判、穿透弹跳过目标、溅射范围抖动 |
| 只做关卡进度存档 | 满足「刷新继续」诉求，实现面极小，自校验简单 | 科技树 / 离线收益 / 云档：需要数值长线设计与后端，超出单页示例边界 |

## 8. 边界与已知限制

- 像素呈现、真机触控手感与音频解锁时序**无法在 Node 侧覆盖**；已用契约与装配测试兜住接口，表现层需人在页面点验。
- 小屏（≤360px CSS 宽）下塔盘压到 78px、字号降一档；再窄会出现塔卡横向滑动更长，不做响应式两列。
- 横屏判定用 `(orientation:landscape) and (max-height:640px)`；平板横屏（高度 >640px）保持竖屏式底部塔盘，属于刻意取舍。
- 无尽模式 40+ 波后是跑分曲线，不再保证「可通关」的平衡；波次数学与敌人数量会快速增长。
- 依赖 Pointer Events，不做 `touch`/`mouse` 事件降级；不支持的环境（旧 Safari）无法游玩。
- emoji 图标依赖系统字体，缺字体的环境显示为方框（无内置图标字体）。
- 中文文案与关卡名较长时靠 CSS 换行与 `text-overflow`，未做多语言。
- 高刷（120Hz）设备按 rAF 原样跑（逻辑固定 60 步），渲染帧率高于逻辑频率属预期。
- 极端连点由音效节流（>16 声部即止）与粒子池上限吸收，不做输入指令队列。
