# AI 球形算力场（WebGL） · 需求与设计

## 1. 需求与目标

- 一句话：复刻参考图「AI 模型疯狂计算中」的视觉——中央一颗由节点与连线构成的发光球体匀速自转，周围粒子带立体纵深运动，底部同名字幕。
- 目标用户与场景：给「AI 算力 / 模型工作中」这类文案做背景素材的人；桌面为主（全屏观赏 + 键鼠交互），移动端可看（触摸拖拽 + 面板调参）。展示的编程能力点是**纯 WebGL 手写渲染管线**（无 three.js）：着色器、FBO 后处理、程序化几何。
- 验收标准：
  1. 打开即自动播放，球体**匀速**自转（角速度恒定，不受帧率影响：`角度 = state.t × 速度`）。
  2. 周围粒子有明显的**立体动感**——透视尺寸衰减 + 距离淡出 + 差分自转 + 相机环绕，四者任一单独可见。
  3. 参考图要素齐备：辉光核心、节点连线球、发光环（含虚线流动）、四角数据流、穹顶透视点阵、底部中文字幕。
  4. 60 fps（桌面独显，1400 粒子 + 辉光），无外部依赖，`file://` 与 HTTP 都能打开。
  5. 控制台无报错：着色器编译/链接通过，无 null uniform location，无 NaN 上传。
- 非目标：不做交互游戏化（通关/得分/音效），不做 2D 降级视图，不做贴图/模型导入，不做存档，不做与首页其它页面的联动。

## 2. 玩法 / 使用流程

纯展示型动画，状态迁移是 `载入入场 → 常驻播放（可暂停）`：

1. 载入：`state.intro` 从 0 线性推进到 1（耗时 1.7 秒，`smoothstep` 缓动）→ 镜头视距 6.4 → 4.15、球体缩放 0.55 → 1.0、所有层透明度 `I` 从 0 → 1。字幕与数字雨由 CSS 动画同时登场。
2. 常驻播放：相机以 0.055 rad/s 自动环绕；球体以 `state.spin`（默认 0.09 rad/s）匀速自转；虚线沿能量环流动、数据流下落、彗星在穹顶划过。
3. 用户介入：拖拽改变偏航/俯仰（带惯性）；滚轮缩放视距 3.0～6.8；面板 6 条滑杆调参；`空格` 暂停（冻结 `state.t`，画面停在最后一帧）。
4. 自动回归：拖拽结束 2.2 秒后，俯仰角以每帧 2% 的比例缓回默认 0.30，偏航保留用户的偏移量继续叠加自动环绕——所以拖完不会「弹回原位」，观感连续。
5. 重置：刷新页面即回到初始状态（无存档）。

## 3. 数据与算法

- 坐标系与单位：右手系，Y 轴朝上，球体半径 `CFG.sphereR = 1.0` 为唯一尺度基准，相机距离 3.0～6.8、远端穹顶半径 3.2～14.3、尘埃半径 1.15～5.75。相机 `fovy = 46°`，`near 0.1 / far 60`。
- 矩阵：自写 column-major 工具（`m4 / m4mul / m4perspective / m4lookAt / m4rotX/Y/Z / m4scale`），与 gl-matrix 的列主序约定一致；模型矩阵在 JS 侧组合（`m4mulN(rotY, rotX, scale)`），顶点着色器只拿 `uMVP × uModel`。
- 球体几何 `icSphere(subdiv, R)`：标准二十面体 12 顶点 / 20 面，逐细分用中点缓存 `mid(i,j)`（同一条边只生成一次中点，保证缝合不裂），中点归一化投到球面 → 细分 2 级得 162 顶点 / 480 棱边 / 320 面。面表去重成棱边表（`Set` 键 `min,max`）后画 `LINES`，顶点画 `POINTS`，棱边中点再投影到球面做「算力节点」点云。
- 均匀分布 `fibSphere(n, R, jit)`：斐波那契球面（`y = 1 - i/(n-1)*2`，`theta = π(√5-1)i`）用于内核球壳；`n === 1` 时必须单独处理除法，否则 `0/0 = NaN`。随机方向用 `randDir()`（`z` 均匀 + 方位角均匀），不复用 `fibSphere(1, …)`。
- 运动：
  - **球体匀速自转**：`spinAng = state.t * state.spin`，`state.t` 按 `dt` 累加（`dt` 截断在 0.05 秒内），所以角度与帧率无关，恒定角速度。
  - **体积差分自转**（尘埃/穹顶）：顶点着色器里 `p.xz = mat2(cos,sin,-sin,cos) * p.xz`，转角 `= uTime * aData.w`，`aData.w = 1.1 / r`（越远越慢）→ 透视上近处横扫快、远处慢，立体动感来自这里。
  - **数据流下落**：`head = fract(uTime*speed*0.12 + colSeed*11.0)`，`yTop = mix(5.2, -2.6, head)`，每段 `-index*0.17`；整列共用同一个 `head` 保证段间刚体平移，`fade` 指数衰减成彗尾。
  - **彗星划过穹顶**：以法向 `d` 建正交基 `(rr, uu)`，`th = uTime*speed*2π + seed*2π - tailT*0.42`，尾迹沿大圆退化为弧线。
  - **环上虚线流动**：`FS_LINES` 里 `k = fract(vT*uDash + uTime*uDashSpd)`，`uDashSpd` 可负 → 双向流动。
- 时间处理：`deltaTime` 步进（非固定步长），暂停 = 不再累加 `state.t`；`visibilitychange` 回来重置 `lastMs`，避免大 `dt` 跳帧。
- 代码锚点：`ENGINE-START/END` 包住「矩阵工具 + 几何生成 + 着色器字符串 + 状态对象 + 渲染循环」，无 DOM 依赖；已用它跑过 Node mock GL 烟雾测试（见 devlog）。

## 4. 渲染与视图

- 渲染分工：**WebGL 负责全部 3D 特效**（球体、粒子、环、彗星、数据流、辉光、背景渐变）；**DOM/CSS 负责文字类图层**——底部字幕、四角 `0/1` 数字雨、参数面板、返回按钮、fps 文本。数字雨放 DOM 是因为要清晰锐利的小字号文字，WebGL 画位图字体不划算。
- 素材：全部程序化，零图片零字体贴图。粒子外形由 `gl_PointCoord` 距离场现算（`pow(smoothstep,2.2)` + 中心白色核），辉光由后处理现算。
- 分辨率策略：`PR = min(devicePixelRatio, 2)`；宽度上限桌面 2400 / 移动端 1500，高度按 CSS 宽高比推算；`resize()` 每帧检查 canvas 尺寸，变化才重建 3 个 FBO（半分辨率 bloom 用 `>>1`）。
- 绘制状态：主 pass 先不混合画背景渐变，之后全程 `blendFunc(ONE, ONE)` + `depthMask(false)` + 关深度测试 → 加色叠加，绘制顺序无关；粒子尺寸 `clamp(size, 1.0, uMaxPS)`，`uMaxPS = min(50*PR, ALIASED_POINT_SIZE_RANGE[1])`（受驱动上限钳制）。
- 后处理链：场景 FBO → 亮通道提取（亮度阈值 0.40，按 `dot(c, 0.34/0.52/0.14)` 归一化避免色偏）→ 半分辨率横向高斯（5 次线性采样）→ 纵向高斯 → 合成 pass 叠加辉光 + 暗角 + 径向色散（按 UV 偏移取 R/G/B）+ 噪点 + 扫描线。
- UI 图层：左上返回门户、底部居中字幕（带省略号呼吸动画）、左下键位提示、右下参数面板（`<details>`，移动端全宽 + 60vh 滚动）、右上 fps（默认隐藏）。
- 降级：无 WebGL context 时显示中文提示面板并隐藏面板/字幕（`#fallback`），不画任何 3D。

## 5. 交互与输入

- 键位表见 README；`空格 / B / F / H` 走 `keydown`，`space` 与 `b/f/h` 都 `preventDefault` 以避免滚动。
- 指针：`pointerdown/move/up/cancel` 统一处理鼠标与触摸（含 `setPointerCapture`，`try/catch` 包住，防止指针已释放时抛异常）；`wheel` 用 `{passive:false}` 才能 `preventDefault` 阻页面滚动；canvas 上 `touch-action: none` 阻止触摸拖拽变成滚动/缩放页面。
- 输入锁定：拖拽期间记录 `dragPtr` 起点与当时的目标角，`camYawTarget / camEleTarget` 只写目标值，实际角度用 `lerp(dt*6)` 平滑 → 拖拽手感有惯性；`state.idle` 在拖拽与移动时清零。
- 视差：`state.mouse.tx/ty` 归一化到 `-1..1`，`parallax` 滑杆为 0 时完全关闭。
- 误触与可访问性：面板是原生 `<details>` + `range`，键盘可聚焦；`aria-label` 标每条滑杆；提示文案不做 pointer 事件（`pointer-events: none`）避免挡住拖拽。未接 `prefers-reduced-motion`（常驻动画，降速即空屏）。

## 6. 状态与持久化

- 运行时状态全在 `state` 对象（时间、暂停、入场进度、相机 6 元组、鼠标视差、显示开关）与 `CONTROLS` 滑杆值。
- **无持久化**：刷新即重置。理由：这是观赏型动画，参数是「调了看效果」的临时量；写 `localStorage` 会让共享页面之间互相污染，收益近零。
- 无 `localStorage` / IndexedDB / cookie；关闭标签页不留痕。

## 7. 关键取舍

- **不用 three.js**：仓库已有 three r128 的 vendor，但本页要展示的就是「手写 WebGL」，且单文件零依赖能 `file://` 直开，比引 vendor 更贴合门户「小参数模型演示」定位。代价是自写矩阵与 billboard 基、bloom 管线。
- **粒子只用 `POINTS` + 加色混合**：几十次 draw call 就能出上万粒子效果，代码量远小于 SDF 公告板网格。代价是点大小受 `ALIASED_POINT_SIZE_RANGE` 钳制、且不能旋转。
- **线宽 1 px**：不写 ribbon 几何，靠 bloom 把 1 px 线糊成发光带；关掉辉光会显得细。换取实现简洁与移动端性能。
- **差分自转放在顶点着色器**：粒子运动不占 CPU，`drawArrays` 的 count 直接当「粒子数量」滑杆用（不重建缓冲）。代价是每层要传 `swirl/bob` 参数。
- **数字雨用 DOM**：文字锐利、零字体纹理；代价是 WebGL 3D 数据流与 DOM 数字雨是两套运动（视觉上刻意错开景深，避免重复感）。
- **相机自动环绕 + 拖拽惯性 + 2.2 秒后回归俯仰**：放弃「纯自由视角」，让无人操作时始终有构图好的环绕运动。
- **入场动画**：1.7 秒的推镜 + 缩放，让「生成感」更强，代价是首帧不是最终构图。

## 8. 边界与已知限制

- 极端窗口：极窄长条窗口（宽高比 > 4 或 < 0.3）时球体会出画面（不做相机自适应取景）；`canvas.clientWidth/Height` 为 0 时按 1 处理，避免除零。
- 低端设备：软件渲染（远程桌面 / SwiftShader）下 bloom 与 2200 粒子会掉帧，靠面板降级；未做「设备能力探测自动降画质」。
- 超长会话：`state.t` 是浮点累加，长时间挂机后 `sin(uTime*…)` 精度下降会让闪烁相位变粗（约数十小时后），刷新即恢复；未做时间取模。
- 浏览器兼容：需要 WebGL 1.0 + `pointer` 事件；`pointer` 缺失的旧浏览器（IE、旧 Safari）不能拖拽，其它功能正常。
- 设计上不覆盖：音频（无音效，不需手势解锁）、多语言（文案硬编码中文）、多页联动、录像导出。
